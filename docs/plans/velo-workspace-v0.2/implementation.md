## 设计决定

- **场景**　Windows 10/11 桌面。首次使用者用短按查找动作，熟练使用者持续按住并沿方向选择。设计按 420 × 424 DIP 核对，预览可切换深浅色、当前应用与编辑状态。
- **操作层级**　完整菜单以可点击的动作片为主，中心圆负责收起，右侧图标打开「编辑布局」。长按先露出 Logo，单区展开后用蓝色描边及动作名确认当前目标。编辑页的主操作是「保存布局」。
- **结构**　用户手绘稿决定独立弧片的空间关系。上区采用两道各三片的弧带，下区采用一道四片的弧带。中心、扇形和应用标签分别着底，空隙露出原桌面。v0.2 的径向方案作为后续产品结构，已有 P0 沙漏原型用于比较原生命中和性能。
- **视觉**　沿用 Velo Launcher 的深海蓝、浅冷灰白和蓝色反馈。使用现有 Velo Logo、Fluent 图标及 Segoe UI 的 Windows 中文回退。中心圆使用内侧描边，扇区描边从系统裁切轮廓向内收，让 Slint 对描边边缘做抗锯齿。
- **字号与状态**　普通弧片使用 `Theme.surface`，悬停使用 `Theme.hover`，手势选中使用 `Theme.selected` 与蓝色描边，键盘焦点另用 `Theme.window-border`。放得下的弧片显示 20 DIP 图标和 12 DIP 短标签。窄弧片、紧凑布局和长按选择态显示 24 DIP 图标，动作名称在中心下方随悬停、键盘焦点或手势高亮切换。无选中动作时显示当前工作台名称。
- **入场**　快捷键和侧键短按先显示中心 Logo，约 48 ms 后展开全菜单，弧片在固定命中区域内完成 108 ms 的小幅展开。长按划选即时更新，高亮跟随指针。开启减少动态效果时直接显示完整菜单。
- **空位与反馈**　默认动作视图隐藏空槽并保留其编号，编辑时显示虚线弧片与「添加动作」。动作失效时为已配置片提供可读原因和编辑入口。应用识别失败显示「默认工作台」。

## 几何与交互契约

**绘制轮廓、系统窗口区域和命中共用几何源。** 420 × 424 DIP 的画板以 `(210,210)` 为圆心。Logo 命中区直径 64 DIP，标签中心在 `(210,272)`，完整态编辑入口的命中区为 30 × 30 DIP，中心在 `(264,226)`。从正上方为 0°、顺时针为正。

- 上区外环半径 `132–198`，从左至右为 `−74…−26°`、`−22…22°`、`26…74°`。内环半径 `64–124`，三片为 `−72…−27°`、`−22…22°`、`27…72°`。内环两侧的图标锚点向外移 8 DIP。
- 下区单环半径 `110–184`。以正下方为基准，左至右偏角为 `−75…−40°`、`−35…−3°`、`3…35°`、`40…75°`，对应画板角度 `180° − 偏角`。标签保持水平。每片保有至少 24 × 24 DIP 的连续可点区域，文字包围盒留出 4 DIP 边距。紧凑布局优先留图标与当前动作名。
- 全菜单只在指针按下与抬起都落在同一有效弧片时提交。`Tab` 和 `Shift+Tab` 依「中心、上外环、上内环、下区、编辑」移动，`Enter` / `Space` 激活，`Esc` 关闭。Logo 先出现时只有中心可点，按 `Tab` 可立即进入全菜单。空缝点到底层应用后由失焦收起。
- 每次呼出冻结 `HWND/PID/TID`、按下时的物理鼠标点、显示器及 DPI，以该点选屏并将整个画板夹进 `rcWork`。保持计算使用有符号物理像素，统一转为 DIP。必要时整板同比缩到 85%，并用图标优先模式守住命中面积。工作区再小则取消此次径向呼出，在设置里报告尺寸原因。
- 长按仍用原始按下点判断 22 DIP 快划。方向与命中基于显示后的 Logo。若边缘夹紧使按下点落在 Logo 外，先显示中心并等光标进入 Logo 再接受方向，避免从可见扇形旁误触。一次按住期间不重设锚点，显示器或 DPI 变化时取消当前手势。短按会打开夹紧后的全菜单。

### 双模式状态机

1. `Idle → PressPending`。只接受已在设置中明确启用的侧键，保存输入时间与前台上下文，界面保持收起。
2. `PressPending → FullMenu`。不足 `180 ms` 且位移从未达到 `22 DIP` 时松开，打开完整菜单。键盘备用键也打开完整菜单，重复触发关闭。入场期间可按 `Esc` 收起，迟到的展开计时器按显隐代次丢弃。
3. `PressPending → HoldCenter → SectorSelecting`。达到 `180 ms` 仍按住时显示 Logo。位移先达到 `22 DIP` 时立即进入长按路径。`dy ≤ −22 DIP` 展开上区，`dy ≥ 22 DIP` 展开下区，纯横移保留中心态。阈值重合时优先处理移动。单区展开后，越过 Logo 外缘再返回圆内才能重选另一侧。
4. `SectorSelecting → Executing → Idle`。进入有效几何时高亮，边界内侧使用最多 3 DIP 的滞回以减少抖动。松开时重新用严格轮廓计算，仍落在当前高亮且有效的同一槽位才发出一次请求。Logo、空槽、间隙和外圈松开均取消。提交立即收起，后台结果独立反馈。
5. `可见态 → Idle`。`Esc`、失焦、上下文失效或输入中断清理本次交互。后台回调携带代次，关闭或重新打开后忽略旧结果。主动收起只在 Workspace 仍持有前台时尝试归还原窗口。外部点击交给目标窗口。

## 实施顺序

### P0 · 径向绘制与原生输入验证

1. 基于当前 Rust + Slint 工作树新增隔离入口 `--workspace-preview=radial`，保留既有 P0 演示作为同机对照。用现有 `WorkspaceWindow` 适配、`geometry`、`hotkey::Service` 和窗口代次逻辑，扩展独立 Workspace 控制器。先以键盘呼出完整径向视图，按 6 + 4 组出位图证据。
2. 把弧段、圆角和标签锚点定义放到可单测的 Rust 几何模块。Slint 用 `Path.commands` 绘制。将同源几何按物理像素展平为多边形，使用 `CreatePolygonRgn`、`CombineRgn` 与 `SetWindowRgn` 合并本帧的 Logo、可见动作片及状态控件。区分窗口区域与逻辑命中，阴影范围始终留在有效形状内。区域安装失败时取消本次显示。优先验证圆角曲线，必要时采用同源细分路径。
3. 在平台层实现线程拥有的 `WH_MOUSE_LL` 服务。预研通过隔离参数 `--workspace-xbutton=xbutton1|xbutton2` 显式启用，产品设置在 P3 接入。回调只捕获选定侧键的按下、最新位置、释放与前台快照。用有界下/上事件与合并移动避免堆积，按事件时间消费。移动和其他按键直接传给 Windows，只有已接纳的一组侧键按下及其释放由 Workspace 消费。全屏、排除的应用或条件未知时透传新的侧键事件。队列异常时取消已接纳的手势并处理配对释放。退出时释放钩子与资源。
4. 关闭鼠标入口时先停止接纳并取消当前手势。已有按下所有权时只允许有限时间排空配对释放，随后卸载。活动手势设置 8 秒上限，超时取消，接下来首次新按开始新序列。钩子异常和安全桌面切换均取消手势，键盘入口保持可用。记录错误类别与计数。

**通过条件**　Software/FemtoVG 都能显示至少六个独立弧片及 Logo。点击中缝和外圈空白送达底层测试窗，侧键按下、移动、释放可在普通桌面实测连续序列。实测不足时先用键盘版迭代，继续验证受影响的输入入口。

### P1 · 双模式选择与取消

1. 实现上面的状态机，以时间、DIP 位移、槽位状态和单调代次为输入。UI 线程只接收状态与渲染模型。只在进入可见态时创建 Workspace 窗口，激活后接收 `Esc`，激活失败则收起。
2. 全菜单、长按和键盘共用槽位模型与动作提交入口。隔离预览先接一个「启动器」命令和少量验证动作。长按高亮即时刷新，释放后仅派发一次。与 Launcher 交接焦点时直接调用已有显隐入口，保留其查询与页面会话。
3. 用伪时钟覆盖 `179/180/181 ms`、`21/22/23 DIP`、快划返回中心、跨区、屏幕边缘和中断。用桌面输入覆盖短按打开后再次触发、普通鼠标点击、真实侧键长按和键盘回退。

**通过条件**　新手能用短按打开后点击「启动器」，熟练路径能完成上划、下划和中心取消。边界与中断样本只产生预期的零次或一次派发。

### P2 · 应用匹配与可用动作

1. 按下时捕获窗口身份。后台按需查询包 AUMID 或已归一化的可执行路径，使用有限容量缓存和代次核对。普通桌面进程优先按完整标识精确匹配，通用宿主及权限受限时使用默认组。首个可见帧使用已经解析的结果或默认组，冻结到本次交互结束。
2. 定义 `WorkspaceAction`、`SlotId` 与有类型的执行结果。Launcher 现有的 `core::launch`、`Runtime::launch` 和平台 Shell 服务承担系统工具及打开目标。Workspace 执行无搜索词的任务，使用专属完成反馈，不把动作记为 Launcher 的搜索使用记录。未来入口复用同一套动作定义。
3. 让启用的动作只有一种执行所有权。Shell 和文件任务进入现有有界队列，队列拒绝或失败时通过 Velo 现有反馈渠道说明原因。发送预置快捷键在收起后核对目标 HWND、PID、线程与完整性级别，确认前台仍是原目标、触发修饰键已松开，才以一批配对按键发送。失败保留清晰提示。发送返回只表示已提交给系统，应用执行结果由目标应用决定。

**首批动作与模板**

- 全局外环从左到右为「文件管理」「计算器」「任务管理」，引用系统目录的 `explorer`、`calculator`、`taskmanager`。内环为「空槽」「启动器」「控制面板」，后两项走 Velo 显隐入口与 `control`。
- 默认组为「下载目录」「文档目录」「图片目录」「空槽」。Explorer 模板将第三格换为「此电脑」，目录按系统 Known Folder 解析，虚拟位置走固定 Shell 目标。
- VS Code 模板为「终端」「命令面板」「查找」「空槽」，映射 `Ctrl+反引号`、`Ctrl+Shift+P`、`Ctrl+F`。Edge 模板为「新标签」「地址栏」「书签」「空槽」，映射 `Ctrl+T`、`Ctrl+L`、`Ctrl+Shift+O`。模板由用户匹配到已识别的应用后启用。环境不支持的快捷键保留说明，可替换成安全的系统动作。

**通过条件**　Explorer、VS Code、Edge 和未匹配窗口各展示相应布局，重复打开时槽位关系稳定。同名不同路径、程序退出、前台切换、管理员窗口和目标收起失败都走安全回退，快捷键未通过真实输入验证时保留为禁用模板项。

### P3 · 槽位编辑与配置

1. 在 Launcher 设置增加「工作台」页，完整径向视图的编辑按钮跳转到当前布局。设置仍采用现有主题、手动保存和错误文案。提供模块开关、键盘备用键、显式选择 `XBUTTON1/XBUTTON2`、按应用排除。默认模块关闭，侧键无分配，备用键建议 `Ctrl+Alt+Space`。注册冲突在设置内显示实际原因，保留已生效的输入与配置。
2. 编辑独立的全局、默认或应用布局。画板展示空槽 `+`，旁边显示逻辑槽位和选中动作。支持从动作列表拖入、交换、替换、清空、恢复默认，以及键盘选择槽位并「移动到…」。保存提交整份草稿，失败保留编辑状态。上下区各自提供 `4 / 6 / 8` 槽预设。四槽单环、六与八槽双环，按外环再内环、从左到右编号。每道环复用相应三片或四片的角度，下区双环采用内环 `80–136`、外环 `144–198`，应用标签仍位于中心留白。切换预设按编号保留赋值，缩减时将不可见槽位视为停用并保留在配置中。
3. 在 `config.json` 增加可选 `workspace` 对象，读取从 `Config::unknown` 的原始值派生独立快照，含内部版本、开关、触发器、预设和应用布局。缺字段走默认。无效或未来版本保持原值并停用 Workspace。复用串行管理 worker 与 `Store::update`，只更新自己拥有的字段。通用保存从当前已提交值保留 Workspace，Workspace 保存以当前 Config 为基础写回自身。设置应用顺序为预留新注册、原子保存、发布状态，再释放旧注册。现有原文备份随 `config.json` 包含本对象。

**通过条件**　保存、重启和备份读回一致。两个设置入口交错提交时各自的字段可保留。损坏片段、未知字段、不可写、热键冲突、侧键禁用和应用删除均各有回归。拖入 `+`、交换和键盘替代路径在独立数据目录实测。

### P4 · 兼容验证与发布准备

1. 运行 `./scripts/verify-rust.ps1 -SmokeTest`。两种渲染器均以不同的 `--instance-id`、`--data-dir` 运行原生专项，补验 Windows 10/11、真实侧键、高权限窗口、安全桌面、全屏、驱动改键、任务栏各边、负坐标和混合 DPI。以实测标注显示与命中边缘、焦点和侧键释放，记录构建身份与失败样本。
2. 记录侧键到可见帧、进入扇区到高亮、松开到派发的 P50/P95。对比干净 `main`、模块关闭、启用未打开、打开后隐藏与可见状态的 PrivateBytes、CPU、线程数和窗口数。沿用现有脚本和同机重复采样口径。默认 Software 构建在实际打开 Launcher 和工作台后，收起并稳定空闲时，整进程 PrivateBytes 目标为 ≤30 MiB，验收上限为 40 MiB。FemtoVG 作为备选构建单独报告资源数据。热呼出延迟与工作台内存增量按既有回归预算核对。[性能复采与内存要求](../../baselines/2026-11-21-workspace-v02/README.md#2026-11-22-当前构建性能复采)
3. 将已完成项和待实机复验项分别登记到 [基线索引](../../baselines/README.md)，补齐开发、使用和故障排查说明。内部测试默认仍以显式启用进入，发布按现有仓库门槛走。

**通过条件**　两 renderer 完整检查与目标桌面矩阵通过，Software 用后隐藏的 PrivateBytes 在验收上限内。原型替换前所有空隙可穿透、取消路径无动作派发、禁用后侧键返回原用途。未覆盖项按原验收范围记录。

后续轨迹手势、二级扇形和细粒度上下文按使用反馈独立规划，动作定义复用 P2 的接口。

## 预览验证范围

本轮交付浏览器交互设计与工程步骤。1440 × 900 视口的 11 组截图通过资源加载、文字对比度和溢出检查。本地 HTML 已验证扇形点击、空隙取消、拖划松开、编辑保存与刷新读回、保存失败保留草稿。预览动作仅更新当前页面，布局保存到浏览器本地。独立看图后已调整内环标签的位置、编辑入口的对比度和图标区分。原生 Win32 区域、全局侧键、进程焦点、双渲染器和混合 DPI 作为实施验收。
