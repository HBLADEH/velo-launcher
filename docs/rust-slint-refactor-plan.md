# Rust + Slint 重构实施方案

- 制定日期：2026-10-28（北京时间）。
- 工作分支：`codex/rust-slint-refactor`，从 `main` 的 `ac2f51ad1317f4abffab2c548af251e48ce16d2b` 创建。
- 行为基线：Velo `0.9.11` 的 Go + Wails + Vue 实现及现有测试。
- 当前进度：RS-07 已完成本机 Windows 11 x64 验证。2026-10-30 在用户协助下补齐两种渲染器的普通权限单次多文件 Explorer 拖放、普通 Explorer→管理员目标的权限边界、管理员同权限 OLE 拖放、管理员文件选择回退/实际输入及退出清理；源/目标权限、原始事件和截图见 [RS-07 补验](baselines/2026-10-29-slint-rs07/followup-2026-10-30/README.md)。两份 exe 与各 49 个源码指纹未变，延续各 26 项 Rust 测试、20 项组件断言、Release/冒烟及 Go/Vue 回归。RS-06 剩余多屏/混合 DPI/拔插、休眠和 Shell 通知区实机项在本机暂缓，将按[跨机器清单](rust-slint-dual-monitor-testing.md)转到用户的双屏电脑复验，G2 不放行，RS-08 业务迁移未开始，默认渲染器未决。本项未重采内存，前序原构建证据继续保留。

目标是在尽量压低常驻内存的前提下，用 Rust + Slint 还原现有页面、动画和 Windows 交互，随后迁移业务与数据。先证明界面与桌面能力可行，再迁移核心逻辑，最后用同机数据决定渲染器与发布方案。任何内存数字在测量前都只是预算，不能写成重构收益。

本方案是本分支后续工作的执行依据。[原轻量化方案](lightweight-optimization-plan.md)与[架构评估](architecture-review.md)保留为历史背景；其中保留 Go/Wails、暂缓完整换栈的路线约束由本方案更新。既有测量证据和行为约束继续有效。

实施范围保持 Windows 10/11 x64。最终应用采用原生单进程 Rust + Slint，不把 Go 后端、WebView 或本地 HTTP 服务作为发布时的常驻依赖；迁移期间现有 Go 工程继续作为行为参照与回退版本。测试中的 Go 对照程序仅用于离线验证。

本轮不扩展 Everything、插件、云同步、组合启动等新功能，避免将新增需求混入框架迁移。

## 2. 工程组织与内存约束

### 2.1 工程安排

先在仓库中新增一个小型 Rust 应用，按实际增长拆模块，不预先建立大量 crate。RS-01 已创建 `rust/` 的 Cargo/工具链文件、build.rs、main.rs 与最小 app.slint；其余目录按后续步骤增长，目标结构如下：

```text
rust/
  Cargo.toml / Cargo.lock / rust-toolchain.toml
  build.rs
  src/
    main.rs                 启动、诊断参数与事件循环
    ui.rs                   Slint 模型与界面事件适配
    core/                   搜索、索引、配置、历史、应用库
    platform/windows/       热键、窗口、托盘、Shell、图标、更新
  ui/                       .slint 页面、组件、主题与动效参数
  tests/                    Rust 行为与数据兼容测试
tests/fixtures/compat/      脱敏的跨语言输入、固定时钟和预期输出
docs/baselines/<日期>-slint-<阶段>/
                            构建身份、测量、截图、差异和结论
```

- 保留现有 Go/Vue 目录和验证入口；Rust 使用独立构建输出，验证完成前不替换现有安装包。
- 选定、锁定 Rust/MSVC 与 Slint 版本并提交应用的 `Cargo.lock`；记录依赖 features、许可证与发行要求。
- 第一阶段核实所选 Slint 版本的 Windows 窗口/事件后端、原生句柄接口、IME、拖放和两种渲染器支持，不预设 API 或 feature 名称可用。
- FemtoVG 与 Software 尽量使用同一窗口/事件后端，分别构建只启用所需渲染器的 Release 程序。实际启用的渲染器必须可观测；禁止静默回退后仍按请求值标记样本。
- 后端、依赖裁剪、LTO 等构建选项逐项记录。可执行文件体积和运行内存分开评估。

### 2.2 从最小验证版开始遵守的约束

1. UI 线程只做输入与界面模型更新；扫描、Shell 元数据、图标提取和文件写入进入有界工作队列，结果回到 UI 事件循环，禁止后台线程直接修改 Slint 组件。
2. 搜索使用预归一化的内存快照，输入时不扫描磁盘、不提取图标。UI 只持有可见项与必要显示字段，避免反复复制完整索引、路径和历史。
3. 按可见范围加载图标；解码缓存设置字节预算与 LRU 淘汰，区分磁盘 PNG、CPU 位图和 GPU 纹理。每次淘汰同时核实 UI 模型与渲染器是否仍持有引用。
4. 第一轮图标缓存预算设为 8 MiB，包含应用持有的解码位图及可观测纹理估算；渲染器内部缓存另测。DPI 变化按需解码，不为每个应用预存全部尺寸。
5. 字体优先使用 Windows 字体与中文回退，避免默认打包整套 CJK 字体；记录字形缓存随中文输入与 DPI 切换的增长。
6. 隐藏后停止装饰动画、重复模型更新和不必要的计时器；保留热键、托盘及现有刷新语义。先保留可复用窗口，再单独比较释放图形缓存的代价，不靠销毁整个 UI 换取漂亮的隐藏内存数字。
7. 不使用强制清空工作集、持续调用内存整理 API 或关闭必要行为来制造低占用。每轮优化同时复测热呼出和图标重新加载。
8. 状态采用可见/隐藏、主页/设置/导入、输入合成/普通输入等明确状态；定时回调与迟到任务不能重新显示已隐藏窗口或覆盖新结果。

### 2.3 初始预算与选择原则

以下是本分支的**初始工程目标，尚未实测**。内存统一按 MiB（1024² 字节）记录，并保留原始字节。RS-04 完成后记录预算是否可行；调整须说明实际开销和取舍，不能直接将超标项标成通过。

| 指标 | 初始目标 | 判定方式 |
| --- | --- | --- |
| 第一阶段固定数据的稳定空闲私有提交 | 全进程树 PrivateBytes 中位数 ≤30 MiB | 两种渲染器分别报告；图标和字体必须实际加载，不能只测空白窗口 |
| 完整功能、可见且稳定空闲 | PrivateBytes 中位数 ≤50 MiB，并较同轮 Wails 降低至少 50% | 相同配置、数据、图标和刷新状态；目标超出时先归因，不以删功能达标 |
| 完整功能、隐藏五分钟 | PrivateBytes 中位数争取 ≤30 MiB | 与热呼出和缓存重建成本一同验收；报告各样本范围 |
| 原项目常驻内存目标 | 保留原有 <80 MB 目标，并明确最终单位与物理内存定义 | 补采私有工作集；PrivateBytes、含共享页的 WorkingSet 求和都不能单独证明物理常驻达标 |
| 搜索 | 1000 项 Service 等效查询 <10 ms；另测 10000 项扩展集 | 分开测搜索内核、完整查询与输入到结果呈现 |
| 冷启动 / 热呼出 | 冷启动 <500 ms，争取 300 ms；热呼出 P95 <50 ms | 到搜索框实际可输入；冷启动样本不足时不宣称分布达标 |
| 空闲与长期增长 | 空闲 CPU 接近 0，缓存预热后反复操作无持续增长 | 连续记录 CPU、PrivateBytes、句柄、线程和缓存数量；不能用单次回落证明无泄漏 |

RS-04 首轮结果：Software 的固定数据可见私有提交中位数为 **6.82 MiB**，FemtoVG 为 **137.21 MiB**；无测量探针的普通原型分别为 **6.62 MiB / 132.67 MiB**。因此 30 MiB 原型预算在 Software 路径可行，FemtoVG 明确未达标，不上调预算掩盖差异。GPU、私有工作集、隐藏态、CPU、显隐后增长及测量限制见 [RS-04](baselines/2026-10-28-slint-rs04/README.md)。其余完整功能、物理常驻、校准启动/呼出与长期目标仍未验收。

优先保证数据、输入法和 Windows 交互正确，其次压低内存，再在预算内最大程度保留视觉。渲染器未决前，两条渲染路径都参与验证；如需简化阴影或光晕，必须附同场景对比和资源数据，保留具体差异记录。

固定数据覆盖：12 个常用项、至少两行系统快捷、固定项、跨分组不满六列、中文长名称、英文长路径、缺失图标和空结果。输入只做测试数据过滤或切换预置结果，不把简化过滤实现当成未来的正式搜索算法。第一阶段的启动动作只记录选择结果，不执行真实系统操作。

输入与渲染检查：

- 首次启动、页面切回及控件点击后无需再次点击搜索框即可输入；中文与英文可选择、复制、粘贴和删除。
- 至少覆盖 Windows 微软拼音的候选框定位、翻页、选词、取消、中英切换；有条件补测用户实际使用的第三方输入法。合成期间 Enter/Space/方向键/Esc 由输入法处理，不能误启动、导航或隐藏。

- 初验 100%、125%、150%、200% DPI 的文字、图标、候选框与布局；第一阶段允许滚动展示 540 高容纳不下的内容，不更改六列规则。
- 一开始就实现可切换的减少动画模式，后续接入系统偏好。录制过程与稳定截图分开，持续动画不混入空闲测量。

**G1 进入条件：** 两种渲染器都完成构建与首轮测量，或有可复现的不可用证据；至少一种能正确输入中文、保持焦点并渲染核心页面；原始资源样本和截图齐备。内存超预算、软件渲染不支持的效果或 IME 问题须有归因与下一步，输入法或焦点阻断问题未解决时不进入大规模业务迁移。RS-04 的结论是可行性判断，最终渲染器留到第四阶段决定。

### 5.2 数据兼容契约

正式数据目录继续为 `%LOCALAPPDATA%\Velo`。验证阶段增加显式 `--data-dir` 或等价测试入口、独立实例标识与可配置测试热键，不能仅更改环境变量就宣称完成隔离。用户数据副本只在本地，公开 fixture 使用合成或脱敏数据。

### 6.1 统一测量口径

- 同一机器、Windows 版本、电源模式、显示器/DPI、输入法、索引、配置与图标数据；记录代码提交、脏工作区补丁、exe SHA-256、工具链、依赖/feature、渲染器及驱动。Wails 使用完整进程树，Slint 也包含其辅助进程；GPU 内存另列，不藏在未统计部分。
- “同机对照”顺序运行三份程序，避免抢占 Alt+Space、单实例锁或写同一数据。固定测试预设可以关闭更新网络检查，但另做默认设置的功能回归，不把受控预设当成全部默认行为。
- 两个 Slint 版本使用同一代码、同一窗口/事件后端和相同构建优化，只改变必要的渲染 feature；记录不可避免的差异，A/B 顺序交替以降低预热影响。
- 扫描完成且动画结束后，在可见稳定空闲、隐藏约 30 秒、隐藏约 5 分钟三种状态各采至少 3 个 15 秒有效样本，记录 PrivateBytes、WorkingSet、私有工作集、CPU、进程/线程/句柄及图标缓存；不可采字段明确留空。
- 另测扫描峰值、首次加载/缓存命中图标、中文字形预热、DPI 切换、快速输入、显隐和设置页往返。至少完成 100 次显隐与 30 分钟操作/空闲循环，观察预热后是否持续增长；峰值与稳定空闲分开报告。
- 暖启动至少 3 次；热呼出至少 20 次真实按键；报告中位数、最近秩 P95、范围、失败数量和原始记录。严格冷启动至少取得 3 个独立冷条件样本，每个系统启动周期最多一份程序计冷启动，三个候选分别补足，不把后续程序的缓存启动算冷启动。小样本冷启动分位数只作观察。
- 启动与热呼出均以搜索框实际接收输入为结束边界，记录窗口出现、首帧、焦点与输入接受等分段时间。输入失败/超时保留，不能用日志“ready”或工具调用耗时替代。
- 1000/10000 项分别测搜索内核、服务查询、输入到结果呈现；图标冷热缓存与系统冷/暖启动是不同维度，分别命名和留证。

现有 [measure-resources.ps1](../scripts/measure-resources.ps1)绑定 `VeloLauncherWindow`、`velo-launcher*.exe` 和 `go version -m`；[计时工具](../scripts/collect-latency.ps1)依赖既有探针。RS-04 必须先增加按 PID/原生句柄识别、Rust 构建身份和 Slint 输入就绪观察，区分应用类型并保留旧采集兼容性；不能原样运行后把缺失字段当成有效结果。优先复用[资源采样](../scripts/lib/resource-sample.ps1)与[延迟汇总](../scripts/summarize-latency.ps1)的有效性和统计规则。

### 6.2 视觉与动画基线

页面内容使用相同 fixture、主题、查询词、选中项和窗口尺寸。现有[实机截图](images/README.md)作为视觉参考，但其中 800 像素宽的物理截图不能直接当作 640 逻辑像素；同轮重新截取 Wails 与两个 Slint 版本，按实际 DPI 对齐。

必验场景：浅/深首页（含固定和空分组）、列表搜索、六列网格搜索、空结果、长名称与路径、右键菜单、自定义应用、七个设置页签、扫描/错误/更新状态、各类原生确认提示。尺寸、间距、圆角、图标、字重、换行、选中和焦点态分别检查；核心控件边界在 100% DPI 下原则上误差 ≤2 个逻辑像素，字体抗锯齿差异单独说明。

| 动效 | 当前源码基线 | Slint 验收要求 |
| --- | --- | --- |
| 首页 tile 入场 | 透明度 0→1，360 ms；每列错开 24 ms，列序号按 `%6` | 保留节奏；搜索网格目前关闭 tile 入场，不为每次输入新增整页动画 |
| 页面/结果内容进入 | 透明度与下移 5 px→0，240 ms | 内容及时可交互；普通显隐沿用原生窗口行为，不额外叠加未有的窗口开场 |
| 悬停与按压 | tile 上移 2 px；图标上移 2 px、放大 1.08；按钮按压 0.96 | 保留幅度与 160–280 ms 过渡，鼠标/键盘选中效果一致 |
| 搜索焦点与列表选择 | 搜索边框/阴影约 180 ms；列表背景/边框 140 ms | 焦点可见，输入与快速选择不受动画阻塞 |
| 页面切换 | 进入 opacity 220 ms / 位移 8 px→0、280 ms；离开 100 ms | 新面板及时挂载，不能等待动画完结才接收输入或拖放 |
| 其他 | 设置齿轮 hover 旋转 35°/350 ms；刷新旋转 1 s；下拉进入 140/180 ms；录制脉冲 1.2 s | 对应状态可用；只在需要时运行，隐藏后停止装饰刷新 |
| 减少动画 | 当前 `prefers-reduced-motion` 禁用动画、过渡和 hover 位移 | 接入 Windows 系统偏好，两个渲染器行为一致 |

当前主缓动为 `cubic-bezier(.22, 1, .36, 1)`。按所选 Slint 版本支持能力还原，不支持的曲线/阴影/光晕先记录，再比较实现成本。静态截图叠加或差异图检查布局；动画用同场景录像逐帧核对时长、轨迹和结束状态，不能用一张截图宣称动效一致。动画期间另测 CPU/帧耗时，不与稳定空闲数值混合。

### 6.3 渲染器与发布决定

两种渲染器先过输入、交互、数据与视觉门槛。性能都满足时优先选择隐藏/可见内存更低、空闲 CPU 更低且唤起稳定的实现；Software 如在高 DPI 动画下 CPU/帧耗时明显变差，或 FemtoVG 的驱动兼容/显存/常驻成本超预算，必须在对照表中明确取舍，不能预先认定胜者。

最终交付包含默认渲染器、必要时的显式回退方式、适用范围、剩余差异、构建与验证脚本、Windows CI、版本信息、安装/免安装包和许可证说明。复用现有更新的校验/备份语义，验证旧版→Rust 升级以及 Rust→Go 回退的数据可读性；替换前退出旧实例，保留数据备份与可恢复程序。

**G4 完成条件：** 四阶段检查有证据，功能与数据无阻断回归；性能目标逐项标注达成/未达成，视觉差异有清单；默认渲染器有同机数据支持；升级/回退与打包可复现。任一未达标项如实保留，不以最终选择渲染器代替整体验收。
