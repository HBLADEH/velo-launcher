# 首次启动焦点修复

公开说明：本页关联的公开结果已脱敏；原始日志与源码快照仅本地保留，见[公开范围与校验口径](../README.md)。

2026-10-28（北京时间）完成代码修复、自动化检查及一次生产模式首次启动的焦点复核。**已观察到无需点击即可获得完整输入焦点；这不是冷 / 暖启动性能目标全部达标的验收。**

## 原因与改动

修复前可出现顶层窗口可见且处于前台、DOM 搜索框已是 `activeElement`，但 `document.hasFocus()` 为 false 的状态。原生焦点停在 `VeloLauncherWindow`，没有交给 WebView 的 `Chrome_WidgetWin_1`。

`SetFocus` 对已经拥有焦点的同一个 HWND 不产生新的 `WM_SETFOCUS`。Wails 依靠此事件调用 WebView2 `MoveFocus`；若宿主在 WebView 就绪前先获得焦点，之后只对宿主重复 `SetFocus`，就无法补上交接。

- `main.go` 设置 `StartHidden`，由应用统一控制首次显示。
- `App` 等待原生初始化与 `FrontendReady` 都完成再决定显示 / 后台隐藏；显式显示或隐藏优先，重复握手不再次激活。
- 隐藏状态也先读取缓存首页再发送前端握手，首次显示无需等待全盘扫描。
- `DesktopWindow.focus` 仅在焦点已停在宿主 HWND 时先清空焦点，再同步设置回宿主，产生真实焦点转换，让 Wails 将焦点交给 WebView。没有增加固定等待时间或后台抢焦点定时器。
- 仅测试构建启用的探针增加最近 DOM 状态与本进程 GUI 线程焦点，方便区分“窗口在前台”和“输入已就绪”；正常发布构建不含探针。

## 实机证据

所有候选使用独立用户数据目录，测试副本关闭自动检查更新；未替换安装版程序或修改原配置。

| 检查 | 结果 | 证据 |
| --- | --- | --- |
| 原代码首次启动 | 窗口可见，输入就绪未确认 | [状态](before-state.json)、失败事件（本地原件：`before-events.jsonl`，不入库） |
| 仅调整首次显示时序 | 原生窗口在前台，宿主仍占有焦点；DOM 输入框已选中，但文档无焦点 | [原生 / DOM 状态](native-before-state.json) |
| 加入宿主焦点转换后首次启动 | 原生窗口在前台，焦点进入 Chrome 子窗口，文档与搜索框均有焦点，输入框可写且已显示 | [状态](fixed-state-01.json)、就绪事件（本地原件：`fixed-events.jsonl`，不入库） |

成功观察来自新建的 WebView 配置，程序为正常生产模式，没有 `--diagnostics`。测试中没有点击窗口或注入查询文字。探针以原生激活和 DOM 就绪共同确认焦点恢复；未完成实际字符输入的额外检查。

该次进程创建到就绪确认的保守上界为 **2187.0876 ms**。这是当前系统启动周期内的一次功能复核，按 `WarmStartup` 记录；不是系统重启后的冷启动，不并入旧 OPT-00 冻结程序的性能分布，不证明冷启动 <500 ms 或热呼出 <50 ms 达标。

成功观察程序 SHA-256 为 `16F4CA7C21CA8488FFE0116DE5B5C208C8EDC8870D50C90F50A74671B6CEFB51`。默认发布程序使用不同构建标签，因此 SHA 不同；[构建清单](build-and-verification.json)保存默认程序路径、大小、SHA、标签和产品运行源码与观察程序一致性的核对。探针后续增加了窗口不存在 / 不属于本进程时不查询 GUI 焦点的保护，产品运行源码未因此改变。

## 自动化检查

- 新增真实 Win32 回归：宿主先获得焦点，模拟子控件稍后就绪，验证再次聚焦能交给子控件。测试在修复前失败，修复后通过。
- 新增应用生命周期回归：原生 / 前端两种就绪先后顺序、只显示一次、后台启动、快捷键不可用时可达、显式显隐不被迟到握手覆盖。
- 新增前端回归：初始隐藏时先取得缓存首页，再发送握手，显示事件后恢复搜索焦点。
- `./scripts/verify.ps1 -SkipBuild` 通过，包含测量工具回归、绑定生成、格式、lint、26 项前端测试、类型检查、前端构建、Go vet 和 Go 测试。
- `go test -tags latencyprobe ./...` 通过。
- `wails build -platform windows/amd64 -o velo-launcher-focus-fix.exe -s -skipbindings` 通过；默认产物位于 `build/bin/velo-launcher-focus-fix.exe`。
