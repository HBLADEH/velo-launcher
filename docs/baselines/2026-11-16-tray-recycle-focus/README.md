# 托盘关闭闪回与回收站确认焦点

日期：2026-11-16。分支 `codex/launch-groups`，基线 `63763d3` 上的未提交增量。当前仅修改 Rust 原生交互，未打包或发布。

## 修改

用户确认托盘问题表现为“点击关闭，先消失又重新出现”。原代码在托盘线程收到 `WM_LBUTTONDOWN` 时查询主窗口是否可见，但 Explorer 可能先触发主线程失焦；失焦计时器隐藏主窗口后，鼠标按下通知才到达，错误捕获为“原本隐藏”，最后 `NIN_SELECT` 又把窗口打开。

本轮在 UI 收到失焦时，只针对按住主鼠标键且指针位于本实例托盘图标范围的手势，记录失焦前的可见状态。托盘线程随后沿用该次点击意图，选择完成后清除；新的按下会替换已取消的旧手势，键盘操作、右键菜单与图标重建也清除状态。左右键交换使用系统当前配置，不修改系统设置。普通点击窗口外部仍走原失焦逻辑，没有延长全局隐藏延迟。

清空回收站的原生确认框默认按钮从取消改为确定，Enter 可直接确认。关机与重启的默认取消保持原行为。取消仍不执行清理、不记录成功历史；空回收站仍为只有确定按钮的提示。

### 实际托盘点击

使用当前已完整验证的 FemtoVG Release 复制出独立预览，指定 `--fixtures --background --instance-id=tray-focus-fix-check`、独立测试目录与 `Ctrl+Alt+Shift+T`。固定样例不执行应用、不写正式业务数据；系统托盘仍为真实 Explorer 通知区。

用户按提示进行连续开关与长按，反馈“开关和长按都正常，没有闪回”。该实例日志记录 **8 次失焦前点击意图保留、8 次明确 Hide、9 次 Open、0 次不确定 Toggle**；其中 7 次为 blur 已隐藏后才处理 Hide，正好覆盖原问题的竞态，最终为隐藏。开头有两次连续 Open，没有对应额外 Hide，不将其错误写成“每次按下严格对应一次显隐”。详见[实测摘要](physical-tray.json)。

只读观察程序另以名义 2 ms 间隔采集本实例 HWND 可见性和自身托盘区域的鼠标键状态，不注入输入。采集上限为 240 秒，用户在临近该上限才开始操作，因此该采集只覆盖部分点击，不能据此宣称完整轮次的逐帧显示或零闪烁；完整反馈来自用户观察及持续的应用事件日志。

首次启动观察程序早于托盘 owner 的异步绑定，报告 owner 未就绪；只读复查确认绑定完成后启动观察程序，保留第一次日志，不把它当作交互回归。测试完成后按 PID 与独立 exe 路径核对并停止预览，观察程序已结束；此处不声称使用托盘“退出”完成正常关机路径验收。

Software 通过同份原生规则、真实确认框与完整冒烟，实际连续鼠标点击只对上述 FemtoVG 预览复验，不扩大到未测驱动、多屏或其他 Windows 版本。

后续使用同哈希 Software Release 准备独立本地试用版，启动、配置就绪与 Alt+Space 注册均核对通过；用户试用后反馈“没什么问题”，并授权提交、推送和合并。该反馈补充本机试用验收，不改变此前各专项的输入方式与适用范围。
