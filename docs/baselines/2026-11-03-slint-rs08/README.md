## 实现

`rust/src/lib.rs` 导出 `core/`，不依赖 Slint 组件或原生窗口句柄。`model.rs` 保留全部 AppItem 字段及原 ID，并实现兼容 ID 和旧图标 URL 的本地缓存路径映射。`config.rs` 固化 version=1 的字段、默认值、枚举和范围；`data.rs` 定义索引、历史、应用库及明确的加载结果；`storage.rs` 提供后台同步 I/O、串行提交和不可变快照。文件提交的 Win32 边界位于 `platform/windows/atomic_file.rs`。

- ID 采用 Go 的逐字符简单小写路径 + NUL + 原参数，SHA-256 前 16 字节十六进制。Rust 的整串小写会改变 Sigma 或展开 U+0130，已由共享用例防回归；读取已有记录不重新计算 ID。
- 有效旧配置只在内存补齐默认值，不修改磁盘原文。保存保留根级/嵌套未知字段和超大 JSON 数值。null、空集合、false/0 以及未知字段的处理分别验证。
- 历史保留查询映射、计数、原时区和 9 位小数时间戳。索引保留文件时间、大小、来源和应用字段，损坏或版本不符时保留原件并返回待重建状态。
- 自定义应用与固定项共同原子提交。只有新应用库缺失时才迁移旧快速启动文件；保留旧文件，已有空新库也不能重新导入旧记录。
- 同目录临时文件写完后 `sync_all`、关闭，再用 `MoveFileExW` + `WRITE_THROUGH` 提交。保存成功后才发布快照，读者不等磁盘提交；失败保留旧文件和旧快照。配置备份与配置保存共享同一 Store 提交锁，复制磁盘原文并禁止覆盖旧备份。
- 常规错误的 Display/Debug 只输出操作类型；源错误保留在 `source()`，避免 Rust 的 Result main 将 tempfile 错误中的个人目录写入普通日志。

当前 API 为同步后台接口，调用方必须先持有实例/数据目录锁，再放入后续业务的有界后台任务。离线 Rust 入口复用既有实例隔离检查，禁止访问正式目录及其子目录，不注册热键/托盘、不扫描磁盘应用、不执行 Shell 动作。

## 共享用例与差分

输入及 Go 生成的预期位于 [共享 fixture](../../../tests/fixtures/compat/rs08.json)，来源和维护步骤见[说明](../../../tests/fixtures/compat/README.md)。覆盖 12 组 ID、30 组配置输入；数据 bundle 包含固定时钟、中文/空格、原 ID、自定义/固定独立语义、null/空数组、正负时区/零时间/纳秒、超出 JavaScript 安全整数范围的文件指纹。

Go 侧使用现有 `Config.Defaults/Validate/Load`、`model.Identity`、`history.Entry`、`indexer.Cache` 和 `storage.Write/Read`。私有应用库额外在 `internal/app/compat_test.go` 直接调用原 `loadLibrary`，核对迁移后实际内容与空新库优先级。

`test-data-compat.ps1` 为每个渲染器建立全新临时目录，分别执行：

1. Go 生成四个业务 JSON → Rust 读取、修改并保存 → Go 和 Rust 按 Go 预期再读取。
2. Rust 生成四个业务 JSON → Go 读取、修改并保存 → Rust 按 Go 预期再读取。
3. 对自己的临时目录设置真实 NTFS 写入拒绝，要求 Rust 保存失败，Go 仍可读取旧状态，并核对四个原文件 SHA-256 不变。结束恢复 ACL，验证入口清理临时目录、进程和实例锁。

修改包含配置、固定时钟下的历史次数/查询记录、同时删除自定义应用及其固定记录；索引完整往返，核对 i64 文件指纹。未知字段保留另由 Rust 测试验证，因为 Go 的类型序列化本来就丢弃未知字段，不能用丢失后的 Go 输出作为保留性预期。

## 明确差异与后续边界

按重构计划有意增强的保护：Rust 保存时保留未知字段；损坏配置先复制原文再替换，因此恢复失败时原路径也保留；损坏历史/应用库返回错误并保留原件，不以空数据替换；未来配置即使其他已知字段解码失败也受保护。Go 旧实现的历史损坏恢复及配置重写语义保留为基线，不反向修改旧业务实现。

新备份名称使用 UTC 时间与独立随机后缀，原文逐字保存，不改名或清理已有 Go 备份。隐藏原始源错误只影响普通诊断格式，调用方仍能按错误链定位具体失败；此阶段尚未连接用户提示界面。

RS-08 没有接通真实搜索、历史学习、应用发现/图标解码、启动动作、完整设置页、快捷键与配置的持久化事务、备份按钮或更新安装链。这些仍按 RS-09～RS-11 实现和验收；RS-08 的备份失败返回值不表示已验证 Rust 更新安装链。

本次没有访问正式数据或真实用户副本，没有新增 UI/IME/多屏实机、内存、CPU、启动或长期稳定性结论。真实旧数据副本的端到端使用与完整功能 G3 仍待后续阶段；默认渲染器未决，保留 Go 构建入口和全部原验收证据。
