## 原采集器失败与修正

这次运行的旧输入观察器没有识别窗口销毁，等待 900 秒后以 `Completed=false / EndReason=Timeout` 保存报告，采集脚本退出码 1；`ValidSampleCountSatisfied=true` 与二十个有效观察分开保留。辅助窗口观察器在退出时抛出 `Cannot read target-window bounds`，没有保存原生坐标/DPI 报告。因此本次没有新增 DPI 或完整轮询报告。

只读 Win32 复现显示：`GetWindowThreadProcessId` 失败返回 0 时，输出 PID 可保留上一次的值。原观察器忽略返回值，可能把已销毁 HWND 误判为仍属于目标进程。已修正两个观察器的返回值检查，增加进程退出检查；窗口几何读取若遇到销毁竞态，正常结束并保留先前观察，仍有效窗口的读取失败继续报错。输入观察器先读取完整末尾日志，再评审结束与样本数量。采集失败提示现在分别显示实际结束原因和有效样本数。

修复期间还发现旧包装脚本在采集结束后才哈希源码，原报告 `ObserverSHA256` 因此指向运行中保存的修订文件。**原报告保持原字节**；启动前记录和修复前保存的完整源码快照共同确认实际加载的旧观察器 SHA-256 为 `2D5494F9B14263E99E7FD0D5AE178481C1B153BB1473BDA1ADEDA92C4B7A0209`。新包装脚本在加载观察器前保存采集脚本和观察器的哈希，避免再次误标。

真实隐藏 STATIC 窗口的销毁回归通过：窗口进程仍运行时，两种观察器都能识别 HWND 销毁；窗口观察保留既有样本，输入观察及时结束并保留无字符失败。此回归不显示窗口、不安装键盘 hook，不作为实机热键样本。最终 `GOTOOLCHAIN=go1.25.6 ./scripts/verify.ps1 -SkipBuild` 退出码 0，包含共享采集回归、前端 26 项测试、lint/typecheck/build、Go vet 与测试，见 [verification.json](verification.json)。本次未重建 Rust 或测量 exe，也未重跑 Rust smoke。
