## 实际字符接收观察

新增被动的 Windows Alt+Space 观察器，仅在指定 PID 的 launcher 隐藏时记录对应热键，不发送输入，也不采集其他按键或查询文字。结束边界来自 Slint 的实际 `input_accepted`，必须组件/原生焦点、可见、非 IME 合成、非管道合成、实际 UTF-8 字节数大于零，且进程正常退出、最终日志无丢失。物理热键通过低级 hook 的注入标志排除自动化按键；暖启动直接由用户从预先准备的资源管理器快捷方式启动。

共 48 条尝试，46 条有效：40 次物理热键和 6 次独立进程暖启动；2 次 IME 合成未计为普通字符样本，原失败保留。Software 初次校准成功的慢样本仍参与 20 次统计，没有去掉最高值。用户确认各次启动均无需点击搜索框即可输入；日志中的每个有效接收时间戳都已与最终原始事件逐一匹配，见[源事件核对](input/source-verification.json)。原始观察 JSON 保留在 [input](input/)，可比较的 CSV 见[全部尝试](input/desktop-latency.csv)与[汇总](input/latency-summary.json)。

这些是**到实际输入接受的观测上界**，包含用户在看见窗口后开始输入的间隔，未扣除人工等待，不能据此认定纯唤起 <50 ms、冷启动 <500 ms 达标或失败。热键事件时钟量子约 15.625 ms，报告映射观察；暖启动使用 OS 创建 FILETIME 和接收 UTC 并加 1 ms guard，该 guard **不是独立校准误差界限**，未用录像/外部时钟确认首次可输入时刻。这些记录也不测结果帧何时呈现。校准后的延迟目标继续待验。

软件输入实例启用了默认的自动网络检查和 30 分钟刷新语义，用户在关于页分别观察到“发布页尚未提供 Rust 安装包/版本更新包”，没有安装或替换程序，随后正常退出，见[默认网络行为记录](default-network.json)。Wails 的实际输入桥已在独立 `latencyprobe` 构建中补齐信任/合成/字节数记录并通过回归；它与官方资源基线 SHA 不同，[测量构建身份](input/measurement-identities.json)单列。Wails 人工热键和暖启动尚未执行，用户暂离后跳过。

## 图标缓存离线对照

使用现有 Go/Rust 图标路径，顺序测试相同 `notepad.exe`、`calc.exe`、`cmd.exe`、`control.exe` 四个系统文件，三轮各用新的应用缓存目录；**保留 OS/Shell 文件缓存**，不叫系统冷启动。每轮首次加载都调用 4 次真实 Shell 提取；随后磁盘命中不再提取，PNG 解码后像素与首次提取相同。Go/Rust 三轮图标键与解码 RGBA 哈希全部一致。

| 四图标一轮范围（ms） | Go | Rust |
| --- | ---: | ---: |
| 空应用磁盘缓存提取/写入 | 14.435–118.945 | 132.927–259.625 |
| 已有磁盘缓存 Populate/加载 | 0.504–1.137 | 0.805–6.005 |
| PNG 解码校验 | 0.529–3.255 | 包含于加载 |

Go `Populate` 的命中路径只检查文件；Rust `load` 同时解码 PNG。Rust 首次路径另含 flush/sync，因此这些计时范围不视为相同范围的语言性能对比。四图标解码合计 65536 字节，PNG 分别为 Go 11892 / Rust 12116 字节，编码不同但像素相同。Rust CPU LRU 的 256 × 4 次引用命中每轮约 0.011 ms，应用 CPU/纹理估算为 131072 字节；这里使用 `Rc<Pixels>` 验证有界缓存引用路径，未创建 Slint 图片或 GPU 纹理，不把它称为 GPU 缓存/实际呈现结果。

原始记录和源码/exe 身份见 [Go](icons/go-icons.json)、[Rust](icons/rust-icons.json)、[对照身份](icons/identity.json)。两份工具都先构建完成再串行计时；早期开发期构建/计时交叠、错误转换编译失败和输出目录已存在的尝试保留本地，不入此表。未更改产品搜索/图标算法，也未上调预算；全量应用图标、动态 DPI/中文 GPU 字形缓存与输入到呈现仍待验。
