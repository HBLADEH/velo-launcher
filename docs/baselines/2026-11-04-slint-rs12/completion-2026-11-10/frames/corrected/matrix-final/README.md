## 同轮条件与结果

复用原冻结 Software/FemtoVG/Wails 实际输入 Release，外部观察器为已通过移动/缩放回归的 build7。第四版合成库为 1000/10000 项、空历史、四个固定项、浅色列表、8 个结果及实际棋盘 PNG；正常后台发现保留，扫描后实际目录数量分别核对。Wails 使用 `latencyprobe` 构建，与无探针官方资源基线分开。机器仍为 Windows 11 x64、本次原生 96 DPI；应用与系统工具的界面/动效差异不因使用相同数据而消失。

按实际采样次序分别记录，未合并不同 renderer/规模的分布。以下都是**物理 A 到结果区域首次像素变化的上界中位数**，不是启动/呼出首次可输入，也不是搜索内核耗时：

逐次值、最近秩 P95、范围、事件时钟量子、QPC/UTC 映射和采集器开销保存在各条件目录；五至七次单查询是小样本，不能当成广泛查询的 P95 或宣称 renderer 全面领先。可见变化与稳定参考区域包含约 240 ms 的页面动效，不能据此判断 1000 项完整服务查询 <10 ms 是否达标；该内核/服务目标继续引用独立 Go/Rust 差分基准。

## 结果内容及帧边界

逐一核对固定查询实际显示的 `RS12 测试 App 00000` 至 `00007` 和棋盘 PNG。Slint 每轮都找到保存图片，其完整结果区 y≥66（全部八行及页脚）的 SHA-256 与检查过的参考像素相同；原图片只留本地。Wails 稳定帧不一定恰在间隔保存图片的时刻，因此使用连续记录的**整客户区 FNV64**与已检查的 Wails 1000 项参考窗口匹配，10000 项也与同一实际画面校验码一致。FNV64 是快速画面一致性检查，不是加密身份或“逐字节比较”的替代名称；两种验证方式在每个条件中明确标注。

各条件的 `result-and-animation-review.json` 保存参考图片原文 SHA-256、参考画面 hash、每个 A 的配对起点、首次匹配完整窗口或已保存结果图、稳定区域时间、变化状态间隔及累计桌面帧数。先变出空区、进入动画、稳定完整结果是不同边界；未把最早变化直接认作精确首个正确结果帧。

`LastPresentTime` 提供桌面合成观察时间，GPU 读回完成时间另列；它不是物理显示器发光时间。帧 cadence/稳定性观察也不代表测到了每帧 GPU 工作或目标程序动画 CPU。几何/时钟检查、PID 创建身份、正常退出和末尾日志检查均通过；没有用工具调用耗时、ready 日志或先前错误的几何裁剪代替这些边界。

## 检查与仍待验项目

本次没有修改产品或采集器实现、重建产品或观察器，沿用已验证的 build7 与第四版工具。最终共享回归入口仍为 Go 1.25.6 的 `verify.ps1 -SkipBuild`，退出码 0，包含夹具实际缓存签名/解码、帧几何/时钟、前端 26 项测试/lint/typecheck/build、Go vet 及完整测试；源码指纹核对见 [verification.json](verification.json)。本轮新增验证是六组真实输入/帧/末尾日志/结果参考/退出身份复核及文档链接、校验和与公开脱敏。
