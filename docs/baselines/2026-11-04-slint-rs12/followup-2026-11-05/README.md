# RS-12 2026-11-05 续验

本页追加本轮 Windows 11 x64 的扫描资源观察及 Wails 实际输入问题。复用冻结程序与隔离数据，不修改原证据身份。**RS-12 仍为进行中，Wails 热键稳定性未通过，默认渲染器未决。**

## Wails 物理热键与人工反馈

实际输入使用单列的 `latencyprobe` 构建，SHA-256 为 `14FB81E432B0543A32DC5E7B1698596A15BB5824136BA045C0AFBB36201B7AFA`；不是官方资源基线的 Release SHA。测量实例为独立数据副本，未启动应用或写入正式业务目录。

首轮观察器匹配到 20 次实际、聚焦、非合成、非 IME 合成的字符接收；其到实际输入的观测上界中位数 652.9185 ms、最近秩 P95 1878.777 ms，范围 321.975–2172.86 ms。这些时间包含人工输入等待，不证明首次可输入的性能目标。用户同时报告“有几轮无法呼出”，表现为“出现一下就消失，或窗口出现但不能输入”。旧观察器在等待输入期间忽略重复热键，到 20 次成功匹配即停止，因此成功匹配数不能证明真实尝试全部成功，也不能据此推算失败率。

随后在同一进程增加只读原生显隐/前台事件，并按五次隐藏起点诊断。用户报告五轮中的第 4 轮失败；观察器记录五次起点，其中一次只有 IME 合成输入而超时、四次匹配到普通字符。记录起点与人工轮次不能一一对应：初始 IME 超时已占一次，原生观察器达到五次起点即退出，随后仍有两条实际输入事件。**不得把观察器第 4 次标为用户报告的第 4 轮，也不得将 IME 超时解释成闪退原因。** 在已覆盖的五次起点中都观察到原生显示和前台切入；这不能排除采集窗之外的失败或组件输入焦点问题。

人工反馈、对应范围与未放行结论见 [结构化记录](wails-operator-report.json)。原始日志与两版采集源码快照留在本地 `.reasonix/rs12-continue-20261105/` 及原会话目录，后续正常退出、最终日志和身份核对单独记录。当前不宣称已定位产品根因，也不修改冻结 Wails 程序消除失败。

原 [20 次匹配](wails-physical-input.json)与[五次起点诊断](wails-diagnostic-input.json)保留原 schema 和采集器指纹，不改标为新模式结果；这些文件中的 `Valid` 仅描述单次字符边界。用户随后从托盘正常退出，退出码 0，[当前状态](status.json)没有 Velo 进程，正式配置、索引、历史和应用库文件原文哈希均未变。原[中间快照](interim-record-identities.json)和[最终文件身份](local-record-identities.json)分别保留。

退出后的[源事件核对](final-input-verification.json)逐条匹配全部 24 条有效字符边界，最终日志无事件丢失，程序 SHA 未变；五次诊断的另一条 IME 超时仍保留。公开 [全部 25 条记录](wails-desktop-latency.csv)明确不建立热键稳定性结论；[原 20 次匹配统计](wails-validsamples-summary.json)与[五次起点统计](wails-physicalstarts-summary.json)按采集模式分别发布，不将两种方法混为可靠性成功率。用户报告的第 4 轮失败不因正常退出或源事件核对通过而被撤销。

## 采集器修正

`collect-rs12-input.ps1` 新增 `-CountMode UntilExit`：有界超时内持续至目标窗口销毁，不因名义成功数或尝试数提前结束；`ValidSampleCountSatisfied` 单列样本门槛。每次物理重试结束前一个未完成尝试并保留失败；注入热键不创建或替换物理尝试；按键自动重复不计新起点。原生事件只保留时间、显隐、前台是否属于目标进程及注入标志，不保存窗口标题、查询或其他按键，最多 512 条，溢出显式标记。

`Completed` 仅表示采集以预期方式结束，不能作为热键稳定性通过。`PhysicalStarts` 仍可用于开发诊断，但不能让人工操作超出其采集窗；正式协助诊断优先持续至退出并核对轮次。原生回调记录不等同呈现帧，也不证明组件焦点或应用层原因。

专项回归覆盖重试不合并、退出前未完成尝试保留、IME/焦点/空字节/合成拒绝、`UntilExit` 超过名义次数仍继续、异常退出与最终事件丢失拒绝。纯规则回归没有安装键盘 hook，不当作新的桌面交互验收。

使用项目记录的 Go 1.25.6 执行 `verify.ps1 -SkipBuild` 通过，含资源/输入采集回归、26 项前端测试、lint/typecheck/build、vet 与 Go 测试；随后新增的导出字段专项复验通过，保留模式、原生事件截断及“成功字符数不建立稳定性”的说明。最初使用 PATH 的 Go 1.23.0 时，旧 HTML fixture 中百分号编码触发 vet 检查失败，原日志保留；没有修改 fixture 绕过，复验按项目工具链执行。本轮未更改产品 Rust 源码、重建或重标冻结 Release；详细工具和日志指纹见[验证记录](verification.json)。

## 启动扫描资源观察

新增 `measure-rs12-peak.ps1` 与只读 Win32 观察器，启动入口可用 `-StartupResourceSeconds 30` 启用。枚举当前根进程及已观察后代，按 PID 和创建时间拒绝复用，记录逐次树、内存、句柄、线程、CPU 原始计数和实际采样间隔。每个快照逐个读取进程，不是内核原子快照；全树瞬时峰值可能高于采样最大值，采样之间出生并退出的进程可能遗漏。GPU 和私有工作集在此入口留空，仍由独立资源入口报告。

Software 开发轮请求 20 ms，1231 个快照全部可读，实际间隔中位数 22.75045 ms、最大 62.6192 ms，启动后约 21.36 ms 开始；私有提交采样最大值 25137152 字节。扫描期间发布新目录、619 个可见项，保留目录/图标警告，正常退出。采集进程在约 30 秒中累计约 31.14 CPU 秒，约占本机总 CPU 6.48%，**此轮保留为高开销开发观察，不作为低干扰基线。** 默认间隔随后调整为 100 ms。

官方 Wails Release（SHA-256 `9A1A898A1E3D70267481BCC68E3368F0B6594F68E8AE43B3F0DCDC06A9B329A6`）在 100 ms 请求下取得 276 个完整快照，实际间隔中位数 108.464 ms、最大 146.8285 ms，启动后约 47.23 ms 开始；进程树最多 9 个进程，私有提交采样最大值 266346496 字节。当前会话扫描日志正常结束，619 项、约 6049 ms；用户正常退出，退出码 0。采集器总 CPU 约 3.448%，仍需保留开销限制。
