## 1. 优化目标与范围

目标是减少后台内存、无效磁盘遍历、重复查询、过大的界面资源及重复构建，同时保持现有搜索排序、固定与自定义应用、快捷键、托盘、更新和持久化行为。

- 优先修复已确认的重复工作；涉及框架生命周期的调整单独验证。
- 保持当前 Go + Wails + Vue 技术栈；本轮不直接开展框架迁移或功能裁减。
- 保留已有原子写入、失败回滚、并发快照、图标跨代保留和单实例保护，这些机制具有实际语义。
- 运行资源、发布包大小与开发目录占用分别记录，不能相互代替。
- 本文记录执行安排与结果；OPT-00 仅固化测量和回归基础，不实施 OPT-01 至 OPT-08 的产品优化，也不替换运行中的安装版。

## 4. 验证与测量操作

命令从项目根目录执行。每项代码改动先跑对应模块的必要检查；集成后运行完整验证，不为纯文档更新重复编译。

```powershell
# 功能、类型、前端构建及 Go 检查；不会重新打包 exe
./scripts/verify.ps1 -SkipBuild

# 最终 Windows x64 构建；-clean 会清理 build/bin，先保留需要的旧产物
./scripts/verify.ps1

# 需要验证安装包时执行，要求已安装 NSIS
./scripts/verify.ps1 -Installer

# 固定条件下的搜索内核基准
go test ./internal/search -run '^$' -bench BenchmarkSearch1000Apps -benchmem -benchtime=300ms -count=3

# 检查依赖定义，输出差异而不改写 go.mod / go.sum
go mod tidy -diff

# 查看根进程并人工确认目标版本与路径；不要把 ID 写死在脚本中
Get-CimInstance Win32_Process -Filter "Name LIKE 'velo-launcher%'" |
    Select-Object ProcessId, Name, ExecutablePath

# 替换为上一步确认的根进程 ID；每次采样 15 秒
$veloProcessId = 12345
./scripts/measure-resources.ps1 -ProcessId $veloProcessId -Seconds 15
```

补充约束：

- 只有 `CPUSampleValid=true` 的稳定样本才参与 CPU 比较；扫描阶段和空闲阶段分开记录。
- 单实例互斥锁、窗口类和全局快捷键跨数据目录共享。仅修改 `LOCALAPPDATA` 不能保证隔离，测试前确认目标程序确实启动；必要时使用独立测试会话，不能把唤起旧实例当作候选构建验收。
- 使用生产模式测量默认隐藏与唤起行为；`--diagnostics` 的可见性与失焦逻辑不同，只用于明确标注的诊断。
- 快捷键到可输入的延迟需要桌面端测量，不能用 `frontend interactive` 日志或搜索 benchmark 代替。
- Home / Service 基准已在 OPT-00 新增，命令与夹具口径见开发说明；遍历计数和刷新计数仍在对应任务实现。现有资源命令不会自动提供这些计数。
